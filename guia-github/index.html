PASO 1 DE 7

De MAXEDRA a GitHub

Preparar su cuenta y elegir cómo trabajar

Objetivo de esta práctica

Cada alumno descargará la plantilla ZIP de MAXEDRA, trabajará en su propia versión y registrará pruebas reales. GitHub guardará el código; GitHub Pages permitirá abrir la aplicación. El informe PDF reunirá la evidencia para MAXEDRA.

El recorrido completo

MAXEDRA → descargar ZIP → extraer archivos → crear cuenta y repositorio → subir archivos → editar → probar → capturar resultados → entregar el PDF.

Crear su cuenta

1. Abra https://github.com/signup en Chrome, Edge o Safari.
2. Siga el formulario: correo al que tenga acceso, nombre de usuario y contraseña propia. Elija GitHub Free si se le solicita un plan.
3. Complete personalmente la verificación y las condiciones del servicio. Abra su correo y confirme la dirección. Revise Spam si no llega el mensaje.
4. Inicie sesión. Anote su nombre de usuario; conserve la contraseña y los métodos de recuperación en un lugar privado. No los incluya en capturas.

Dos formas de realizar el mismo trabajo

OPCIÓN A · Celular o tablet: suba los archivos extraídos y edítelos en github.com. Pruebe en GitHub Pages.
OPCIÓN B · PC: edite los archivos en un editor de texto y abra index.html en el navegador. Después suba su versión a GitHub y publique. Puede combinar ambas si sincroniza sus archivos.

Compruebe antes de continuar

Debe poder iniciar sesión en su propia cuenta. Cada estudiante usará su repositorio, no la cuenta del docente. Para exponer, explique: repositorio = carpeta de código en internet; commit = cambio guardado; Pages = página donde se ejecuta este HTML y JavaScript.

PASO 2 DE 7

Descargar y extraer la plantilla

Use el ZIP actualizado de MAXEDRA

Descargar desde su curso

Entre a MAXEDRA → ET505 → semana 7 → recurso Planificador de materiales — plantilla y ejecución. Descargue el ZIP. Si el recurso abre Drive, use Descargar. Trabaje con la versión que muestra los mensajes de error en rojo.

Extraer antes de subir

En Windows: clic derecho sobre el ZIP → Extraer todo.
En celular o tablet: abra el ZIP desde la aplicación Archivos o el administrador de archivos y elija Extraer o Descomprimir. El nombre de la opción cambia según el dispositivo.
Abra la carpeta obtenida. No edite archivos directamente dentro del ZIP.

Debe encontrar estos cuatro archivos

index.html: pantalla, campos y botones.
styles.css: apariencia y color de los mensajes.
app.js: cálculos, validaciones y acciones.
README.md: descripción del proyecto, ejecución y aportes.

Conservar su trabajo

Guarde una copia original del ZIP. Si ya avanzó, conserve también su carpeta anterior. No sustituya sus archivos personalizados sin guardar una copia. Los tres TODO son partes pendientes de completar; no indican que la descarga esté dañada.

Crear un repositorio propio

En GitHub, pulse + → New repository. En Owner, elija su cuenta. Escriba un nombre breve, por ejemplo et505-planificador. Elija Public para publicar esta práctica con GitHub Free. No agregue otro README: la plantilla ya incluye uno. Pulse Create repository. No necesita ingresar una tarjeta para este flujo gratuito.

Compruebe antes de continuar

El propietario que aparece arriba debe ser su usuario. Use sólo código y ejemplos ficticios en el repositorio público; el PDF con datos personales se entrega en MAXEDRA.

PASO 3 DE 7

Subir los archivos a GitHub

El ZIP descargado se descomprime antes de cargarlo

Subir por primera vez

1. Abra el repositorio que acaba de crear. Si está vacío, pulse uploading an existing file. Si ya tiene archivos, use Add file → Upload files.
2. Pulse choose your files o el selector equivalente. Entre a la carpeta descomprimida y seleccione index.html, styles.css, app.js y README.md.
3. Espere a que termine la carga de los cuatro archivos.
4. Escriba un mensaje como Plantilla inicial de ET505 y pulse Commit changes. Si se ofrece la rama main, guarde en ella.
5. Regrese a la pestaña Code y abra uno de los archivos para verificar que se guardó.

Así debe verse su repositorio

et505-planificador
index.html
styles.css
app.js
README.md

Dónde deben quedar

Los cuatro archivos deben estar juntos en el nivel principal del repositorio. No suba sólo el archivo .zip: GitHub Pages no lo descomprime para ejecutar el proyecto. Tampoco suba la carpeta contenedora completa si eso deja index.html dentro de otra carpeta.

Si usa el celular

El selector puede mostrar Descargas o Archivos. Si no permite seleccionar varios archivos, puede cargarlos uno por uno en el mismo lugar. En GitHub use el navegador; la opción Sitio de escritorio y la orientación horizontal pueden facilitar la edición.

Compruebe y tome su primera captura

Debe ver los cuatro nombres y su usuario en GitHub. Capture esa pantalla como evidencia de organización. Ver los archivos en la lista de carga antes de Commit changes no confirma que hayan quedado guardados.

PASO 4 DE 7

Opción A Editar desde GitHub

Para celular tablet o PC con navegador

Hacer un cambio y guardarlo

1. En SU repositorio abra app.js.
2. Pulse el lápiz Edit this file; si está oculto, revise el menú de opciones del archivo.
3. Busque TODO 1, TODO 2 y TODO 3. Complete un cambio a la vez siguiendo la guía de programación. Mantenga las funciones que ya muestran los mensajes.
4. Pulse Commit changes. Escriba qué hizo, por ejemplo Completar cálculo del total. Confirme en main.
5. Vuelva a abrir app.js y compruebe que su cambio aparece guardado. Si creó otra rama, deberá incorporar el cambio a main para publicarlo.

Qué personalizar y en qué archivo

index.html: nombre del sistema en <title> y <h1>, actividad, material de ejemplo y presupuesto visible.
app.js: tres pendientes y limites.presupuestoCentimos. Elija presupuesto propio distinto de S/150, entre S/50 y S/300, múltiplo de S/10.
README.md: propósito, instrucciones, cambios, pruebas y ayuda recibida.
styles.css: colores o presentación opcionales; conserve la distinción entre errores rojos y resultados válidos.

Editar y ejecutar son acciones diferentes

github.com muestra y guarda el código. GitHub Pages abre la aplicación. Mantenga dos pestañas: una con app.js para editar y otra con su página publicada para probar. Active Pages siguiendo la página 6. Tras cada guardado, espere a que termine la publicación antes de recargar la aplicación.

Qué capturar

Guarde capturas legibles de sus tres cambios y de la personalización. Añada una explicación breve de lo que recibe, calcula o devuelve cada función. Una captura del código no sustituye las pruebas de funcionamiento.

PASO 5 DE 7

Opción B Trabajar localmente en una PC

Edite pruebe y después actualice su repositorio

Preparar su carpeta

Extraiga el ZIP de MAXEDRA en una carpeta de trabajo. Mantenga juntos los cuatro archivos. Haga una copia antes de empezar. Puede programar y probar sin conexión; necesita internet para descargar, subir y publicar.

Editar y ejecutar

1. Abra app.js con un editor de texto, como Bloc de notas o Visual Studio Code si ya lo tiene instalado.
2. Complete los tres TODO y guarde con Ctrl + S.
3. Abra index.html con Chrome o Edge. Después de cada cambio, guarde el archivo y recargue el navegador con Ctrl + R.
4. Personalice también index.html y README.md. Mantenga el nombre app.js, sin agregar .txt.
5. Ejecute las pruebas y capture resultados reales. No necesita instalar Node ni un servidor para esta plantilla.

Subir su versión a GitHub

En su repositorio use Add file → Upload files. Seleccione los archivos actualizados desde la misma carpeta de trabajo. Mantenga los mismos nombres y la misma ubicación para actualizar los existentes. Revise lo que se va a guardar y confirme con Commit changes. No elimine el repositorio ni cree otro para cada modificación.

Continuar en otro dispositivo

Antes de cambiar de PC o pasar al celular, suba sus últimos cambios. Si luego editó en GitHub, descargue la versión más reciente con Code → Download ZIP y extráigala en otra carpeta. Use esa versión como punto de partida; no vuelva a subir una copia local antigua porque podría reemplazar los cambios nuevos.

Compruebe antes de continuar

Abra app.js en GitHub y revise que contiene su última versión. Compare el nombre y presupuesto de la pantalla con su código. Ahora publique y pruebe también la copia de GitHub Pages.

PASO 6 DE 7

Publicar con GitHub Pages

Convertir los archivos del repositorio en una página que se puede abrir

Activar la publicación

1. Abra SU repositorio en GitHub y entre a Settings → Pages. En un celular, Settings puede estar en el menú de pestañas.
2. En Build and deployment, Source, seleccione Deploy from a branch.
3. En Branch elija main; en carpeta elija /(root).
4. Pulse Save. Espere a que finalice la publicación.
5. Abra el enlace o Visit site que aparezca en Pages. Puede consultar el progreso en Actions. Los cambios no siempre aparecen inmediatamente.

Qué debe abrirse

Debe ver su Planificador, no una lista de código. La dirección de ejemplo sería https://SU-USUARIO.github.io/et505-planificador/; sustituya SU-USUARIO o, mejor, copie la dirección exacta que GitHub muestre. Este ejemplo corresponde al ZIP subido con index.html en la raíz.

Trabajar de forma remota

Cuando guarde un cambio en main, GitHub actualizará la página. Espere a que termine la publicación, recargue y pruebe. Para revisar desde otro dispositivo basta abrir el enlace público. Para editar, debe iniciar sesión en la cuenta propietaria del repositorio.

Si aparece un error al publicar

404: compruebe que terminó la publicación, que index.html está en la raíz y que seleccionó main y /(root).
No carga diseño o botones: revise que styles.css y app.js estén juntos con index.html y con esos nombres exactos.
No aparece su cambio: compruebe que guardó en main, revise Actions y recargue.
No encuentra Pages o Settings: confirme que está en su repositorio y no en el del docente.

Alcance de esta publicación

GitHub Pages ejecuta esta aplicación estática de HTML, CSS y JavaScript. El proyecto simula un pedido y no guarda datos al recargar ni realiza compras. Publicar la página no añade una base de datos. Mantenga información personal y contraseñas fuera del sitio.

PASO 7 DE 7

Registrar pruebas y entregar el informe

La evidencia debe corresponder a su propia versión

Pruebas que debe realizar

1. Válido: Cuadernos, 10 unidades a S/5 → total S/50 y saldo igual a su presupuesto menos 50.
2. Inválido: deje el material vacío o escriba cantidad 2.5 → error rojo.
3. Límite exacto: 10 unidades con precio presupuesto/10 → saldo cero.
4. Exceso: aumente ESE PRECIO en S/0.01. Con presupuesto S/150, pruebe primero 15.00 y luego 15.01; no cambie el precio a 0.01.
5. Confirme un pedido válido e intente otro inválido → conserva la ficha válida; después pulse Limpiar. Pruebe Comprobar pedido y Confirmar simulación.

Qué debe mostrar el error

Al comprobar: Pedido no válido. Al confirmar: No se pudo confirmar el pedido. Debe verse el motivo en rojo y aclararse que la ficha anterior sigue siendo el último pedido válido. Si aparece PENDIENTE o TODO, falta completar programación; eso todavía no es una prueba aprobada.

Tomar capturas útiles

En Windows puede usar Win + Shift + S. En celular o tablet use la función Captura de pantalla de su dispositivo. Capture la entrada y el resultado juntos; conserve el enlace visible cuando pruebe la página publicada. Evite incluir contraseñas, correos privados o códigos de verificación.

Armar el PDF mientras trabaja

Inserte cada captura en su informe. Escriba: datos ingresados, resultado esperado, resultado obtenido y corrección aplicada si falló. Incluya código explicado, personalización, organización de archivos y aportes del README. Puede usar Word o su editor de documentos habitual y exportar a PDF. Abra el PDF para verificar que se lea completo.

Comprobación final y entrega

Mi cuenta y repositorio son propios; los archivos están guardados; el código coincide con la pantalla; ejecuté las cinco pruebas; mis capturas son legibles; el PDF explica mis cambios.
